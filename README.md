# WPAI Constitution

The [canonical GitHub repository](https://github.com/MrWizard94-Compile/Agents-Constitution)
is the single source of truth for WPAI's agent quality law, operating process,
skill loader, and verification tools. The accepted `main` commit SHA, not a
local folder name, identifies the binding revision. The prior SOUL and AGENTS
Constitution files are historical inputs; they are not competing law.

Start with [`SKILL.md`](SKILL.md) for how an agent loads and evolves the law,
[`AGENTS.md`](AGENTS.md) for the Definition of Done and 15-point Section 0
gate, and [`SOP.md`](SOP.md) for execution. The applicability matrix selects
scoped `law/*` files. [`governance/EVOLUTION.md`](governance/EVOLUTION.md)
controls source freeze, one meaningful improvement per top-level call,
review, and mirror propagation. [Architecture](docs/ARCHITECTURE.md) and the
[historical-source record](docs/SOURCE-INVENTORY.md) explain the migration.

## Verify source

From a clean checkout, run:

```powershell
python -m unittest discover -s tests -v
python tools/validate-source.py
```

Both commands must exit 0. CI runs the same checks and screens each PR with
`python tools/evolution-guard.py --base <base-commit>`. The guard compares
committed content against the merge base, requires an increased `VERSION`
and changed ledger, and excludes release metadata, exact unchanged-content
renames, and `.github/` changes from its candidate list. Known version fields
in `AGENTS.md`, `SOP.md`, `governance/EVOLUTION.md`, `SKILL.md` frontmatter,
and `SOURCE.json` cannot qualify by themselves. JSON formatting is ignored;
other source whitespace is preserved because indentation, Markdown structure,
and string contents can change behavior. Invalid source-manifest JSON fails
closed. The existing exclusion of workflow-only changes remains in force.

A pass identifies source-content candidates; it cannot prove usefulness or
reject every typo, cosmetic edit, duplicate rule, timestamp, or harmful
change. Mode-only and path-only behavior changes also need a separate review;
they do not establish a content change. Review the actual improvement against
`GOV-EVOLVE-001` and its falsification evidence. A passing source check is not
proof that a local mirror, project pointer, runtime, or published release has
been updated.

The canonical `main` ruleset is a GitHub repository setting, not a Git file.
Audit its live, effective controls separately with an authenticated `gh` CLI
session (the public API omits bypass-actor details):

```powershell
python tools/check-repository-ruleset.py
```

Exit 0 means the active ruleset requires a pull request and a strict passing
`validate` check from the GitHub Actions app, blocks force-push and deletion,
and requires zero approvals with no bypass actors. Exit 1 means policy drift.
Exit 2 means GitHub could not be verified; neither source CI nor an offline
fixture proves the live setting.

## Verify the frozen revision

A top-level skill call reads binding law from one frozen commit. Confirm that
a checkout is that commit, byte for byte, before relying on it:

```powershell
python tools/check-frozen-load.py --sha <full-40-hex-sha> --loader <running-SKILL.md>
```

It exits 1 unless HEAD is the full SHA, tracked files are unmodified, and every
`SOURCE.json` binding file has the exact bytes of its Git blob. The optional
loader comparison prints `STALE LOADER` or `LOADER AHEAD` when the running
`skill-version` differs from the frozen law; follow the frozen `SKILL.md` and
name both versions in the handoff. Text from a summarizing page reader or
search snippet is orientation only. A pass proves the text is faithful to that
commit, not that the commit is accepted `main` or that any mirror uses it.

## Install generated local mirrors

After the accepted `main` commit is verified:

```powershell
python distribution/sync.py --ref main
```

The defaults are in `SOURCE.json`. The sync resolves one immutable SHA,
downloads all binding files, and checks every target before writing. A batch
undo journal in the first target protects prior generated bytes and the
provenance manifest. Ordinary installation failures roll back all targets;
after process interruption, rerun the **same ordered target list** to finish
rollback or committed cleanup before a new install. A post-interruption local
edit or damaged journal stops recovery for inspection rather than overwriting
it. The tool records per-file hashes and removes only files named in a
previous generated manifest. Unknown local files are not deleted.

If GitHub is unavailable after an interruption, recover the existing batch
offline by supplying its original ordered targets explicitly:

```powershell
python distribution/sync.py --recover-only "$HOME\.grok\skills\wpai-constitution" "$HOME\.codex\skills\wpai-constitution"
```

This example uses the default target order in `SOURCE.json`; replace both
paths if the interrupted install used explicit targets. For a single-target
install, supply only that target. Recovery completes the recorded rollback or
committed cleanup; it does not fetch or install new law. If recovery reports
a conflict or damaged backup, preserve the journal and inspect the affected
files before any manual change.

Each file replacement is atomic, but a concurrent reader can observe a
temporary mixture of revisions during installation. Sync and `--recover-only`
hold non-blocking, process-owned locks on **every** target, acquired in stable
path order. An overlapping batch fails before recovery or generated-file
writes, even if it lists the targets in a different order. Retry after the
other process exits; do not manually remove a journal while a process is
running. Each target retains an empty `.GENERATED-MIRROR.lock` control file;
its presence alone is not a stale lock, and it must not be deleted because a
concurrent process could then lock a different file. The control file is not
binding law or part of the generated manifest. A nonempty or symlinked file
at that name is preserved and rejected for inspection. Do not treat an
unverified in-progress mirror as binding law. Locks coordinate this installer,
not arbitrary readers or third-party writers. The batch journal protects
against ordinary exceptions and interrupted processes; it is not a guarantee
against filesystem corruption or lost writes after a power failure. A legacy `agents-constitution` install
must be reviewed and retired separately; it is never silently promoted to
source.

Project adoption uses [`templates/PROJECT-POINTER.md`](templates/PROJECT-POINTER.md)
with project mission, stack, and acceptance in that project's own repository.
Do not vendor editable law into each project.

The [quality assurance map](docs/QUALITY-ASSURANCE-MAP.md) helps select
domain-specific evidence and independent oracles. It does not waive Section 0
or turn a green test result into a claim of complete acceptance.

Before retiring an old project pack, run the read-only consumer audit:

```powershell
python tools/check-adoption.py <project-git-root>
```

The bounded text scan includes native/JVM and shell source/build languages as
well as Markdown, configuration, and JS/TS/Python: compiled CLI help can be an
active governance consumer. The explicit suffix list is in the checker; binary
artifacts and dynamic data flow still require separate consumer inspection.

For a local project directory that is ignored by its parent Git repository or
has no Git root of its own, target the exact directory explicitly:

```powershell
python tools/check-adoption.py <project-directory> --filesystem
```

Filesystem mode scans first-party source and built output regardless of the
parent ignore rules. It excludes known dependency caches; linked paths,
nested Git repositories, and scan limits prevent a clean result. Do not use
a parent repository scan as proof that an ignored child was inspected.

The default Git mode checks tracked and unignored project files plus bounded
ignored `.agents`, `.claude`, `.codex`, and `.grok` locations for retired SOUL
files, pre-pack backups, old-pack loaders, and old packs. It does not crawl
arbitrary ignored dependency trees. Before inspecting each file, it checks
every path component from the project root outward. A linked file or parent
directory (including a Windows junction) is reported as unresolved coverage,
even when Git still lists tracked files below it. Both modes reject a project
root reached through a link; pass the reviewed real project path instead.
Use a quiescent tree: these checks do not provide atomic protection against
another process replacing a directory between the check and the read.
It also detects explicit declarations of active SOUL law. Resolve old CI,
generator, manifest, pointer, and UI references before the old tree is removed.
Keep recovery in Git history, not in a second active working-tree law copy.
A clean static audit is not a substitute for indirect-consumer review or the
project's build and runtime checks.

## Inventory local Constitution copies

The read-only scanner hashes candidates and records access errors. For a broad
PC inventory, name each intended root and choose an output outside the scanned
roots when practical:

```powershell
python -u tools/inventory_copies.py --root C:\ --root D:\ --root E:\ --output "C:\WPAI\WPAI Constitution\.local-audit\inventory-2026-10-12.json"
```

The scanner excludes its own output and checkpoint files when they sit inside
a scanned root. It writes `<output>.checkpoint.json` atomically after each
1,000 completed directories and prints durable progress. If interrupted, rerun the
same command with `--resume`; root order, output, and text-size limit must
match. `--checkpoint-directories` adjusts the interval when a shorter recovery
window is needed. A final report is created **only** after traversal has
finished. Its `status: complete` means the traversal attempt ended, **not**
that all paths were readable. Report schema 3 has a separate
`coverage.status`, per-root `root_results`, and an explicit no-link-traversal
scope. An inaccessible named root is marked `inaccessible`; an error below a
root marks it `partial`. When any access error remains, the final report is
still retained for triage, but the command prints `INCOMPLETE COVERAGE` and
exits 2 instead of printing `PASS`. Inspect those gaps before any cleanup or
absence claim. A no-error result says only that no access gaps were recorded
under the declared no-link policy; it does not prove linked targets or
excluded content absent. Older schema-2 reports have no coverage field: use
their error list to assess gaps, never interpret `status: complete` as full-PC
coverage. The checkpoint is intentionally retained as recovery evidence. Use
a new output name for a new scan, rather than replacing a prior report.

The scanner now recognizes pre-pack `SOUL.md` and `AGENTS.md` backups by
filename even if their bodies contain no known Constitution signature. Older
reports may have omitted such copies. Re-scan relevant roots with this version
before claiming their backups absent; do not rewrite a dated report in place.

Resume validates each queued directory against every named root independently;
unrelated Windows drive letters do not abort the scan, while a queued path
outside all roots (including through a reparse-point parent) is rejected.

The public repository deliberately omits raw private project variants,
machine-specific paths, credentials, and local cleanup manifests. See the
source inventory for what is and is not yet reconciled.
